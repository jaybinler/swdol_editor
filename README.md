# 轩辕剑网络版 · 道具工坊

Windows 本地内容编辑与查看工具，当前版本 **0.10.1**。

## 功能

- 按名称、编号和分类查看道具，展示原游戏图标及已确认属性。
- 支持 27 项数值属性编辑，包含武器伤害力／延迟／距离、六项抗性及体力／灵力回复；属性概览与当前表单同步，保留零值和负值。
- 回避率直接展示。原始御劲非零时保留原值；原始御劲为零且原始回避率非零时，御劲按用户确认规则跟随当前回避率显示，并标记“随回避率”。联动不修改御劲原始字段。
- 预览原始三维资源与部分人物穿戴效果，支持旋转、缩放和线框。
- 人物穿戴的“自动匹配”根据道具要求的种族和性别选择基础人物，按 ACT 应用经过校验的身体贴图；也可手动指定基础人物。
- 明确区分查看、编辑与新增道具。编辑时固定原 ID；新增时可按名称、编号、分类选择模板，复用原图标和模型。
- 新增自动建议双端及草稿均未占用的 ID；支持同一模板多次新增，草稿可重新打开、恢复表单和移除。
- 保存本地草稿，点击后自动备份并覆盖已配置的双端文件；备份仅保留最近一次，支持失败回滚及中断恢复。切换前保护未暂存输入，旧版草稿保持兼容。
- 按出现地图查看 NPC 与怪物，统一预览模板基础外观。
- 每件道具提供“掉落怪物”列表，显示怪物名称、编号和地图；点击名称可直接进入 NPC 页签并精准选中，返回时保留道具未暂存内容。
- 地图索引合并存档关系与已解析的脚本生成关系；枯石等无直接存档的怪物也可按地图查找。关系保存在 v3 快照，离线查看无需原始脚本。
- 每种 NPC／怪物展示一份模板配置的物品清单，页面只显示“道具、掉率”，掉率为已计算的生成百分比。
- 集中配置游戏文件、NPC 快照与只读数据库连接，真实校验通过后才能保存；可用 Windows DPAPI 保护保存的数据库密码。

## 从源码运行

需要 Windows、Python 3.11 或更新版本，以及 Node.js／npm。

```powershell
git clone https://github.com/jaybinler/swdol_editor.git
cd swdol_editor/editor
npm ci
cd ..
.\启动道具编辑器.cmd
```

启动器会准备项目专用 Python 环境。打开本地页面右上角“设置”，选择匹配的客户端根目录、服务端 Object 文件及 NPC 数据来源，通过校验后保存。

本仓库只提供工具源码、测试和示例，不包含游戏客户端／服务端资源、数据库原始文件、NPC 快照、本机设置、密码、草稿、迁移包或内部研究记录。运行时需要自行准备游戏资源。

NPC 离线模式需要与服务端 Object 基线匹配的最小快照；数据库模式需要可读取 npcpool 与 npcpool_add_on 的连接、兼容 MySQL 客户端和区域目录。区域目录应包含地图配置、NewLocalServer.exe 与 ASM/TALK 编号脚本；只读校验后将解析关系写入快照。切换机器后重新定位路径、输入凭据并校验。数据库查询限于两张 NPC 表的白名单读取，页面使用本地快照。旧 v1／v2 快照仍可查看，但需更新 v3 才能补充脚本地图。

## 新增与编辑道具

1. 编辑现有道具：选中道具，点击“编辑道具”，修改名称、说明和已开放的基础属性，再点击“暂存修改”。原 ID 固定。
2. 新增道具：点击道具库的“新增道具”，搜索并选择模板；也可在详情点击“以此为模板新增”。确认新 ID、名称与属性后点击“暂存新增”。
3. 新增继承原始基线模板，独立于该模板的修改草稿；同一模板可新增多件。编号建议不预留 ID，暂存时仍会核验占用。
4. 从“补丁草稿”重新打开可继续修改；“恢复表单”返回进入表单时或最近暂存的内容。“移除”只移除所选草稿。
5. 在设置中填写“服务端 Object.dbf 覆盖目标”，校验后保存。此项与“服务端 Object.dbf（读取基线）”独立，可以填写本机文件或已登录的 Windows 共享完整文件路径，例如 `\\服务器\共享名\qingfeng\Object.dbf`。
6. 核对草稿差异，再点击“导出并覆盖双端文件”。目标为配置中的服务端文件、客户端根目录下的 `Main/Object.dbf` 和 `Main/Language.DBF`。目标文件必须与编辑基线一致；高级客户端路径须与这两个 Main 文件一致。
7. 覆盖前备份到 `output/editor/backups/latest/`，包含三份原文件及必要的设置状态、路径和哈希清单。正常完成后只保留最近一套自动备份，已有历史离线补丁包保留。
8. 覆盖成功后自动载入新基线，清空本轮已应用草稿，保留旧工作区草稿，并在保持数据来源模式的同时更新 NPC 快照绑定；无需每次重新连接数据库。

升级到 0.10.0 后需重启编辑器服务并刷新页面，旧服务不会启用新的覆盖按钮。覆盖前应退出游戏并停止占用这些文件的服务，避免其他程序同时改写。文件覆盖完成不代表运行中的游戏已重新读取数据；加载后的实际效果仍需游戏内验收。

程序会先完整生成并校验补丁、完成本地备份并暂存所有替换文件，然后逐个替换、读回核验。覆盖中失败时回滚并保留草稿；若外部修改、共享断线或权限问题使回滚不能完成，将列出未恢复文件并保留备份。中断后再次启动会先尝试恢复，再读取设置。三个文件跨目录替换不具备整体原子性。

0.7.0 编辑范围新增抗火、抗水、抗风、抗雷、抗光、抗暗（整数 -128 至 127）及体力回复、灵力回复（整数 -32768 至 32767）。旧草稿缺少这些字段时从对应模板补齐。御劲显示联动由原始模板决定：若原始回避率与御劲均为零，之后只修改回避率不会启用联动；原始御劲非零时始终优先显示原始御劲。升级后同样需要重启编辑器并刷新页面。

## 开发与测试

0.9.0 将伤害力、延迟和距离集中到“武器属性”，可在概览查看并在编辑表单修改。0.9.1 起仅“武器/副手”分类显示这三项，其他类型的概览和表单均隐藏整个武器属性区域，原有数值及草稿保留。距离为有符号 16 位整数，伤害力同样为 16 位，延迟为 32 位；均沿用客户端原始显示值，不换算单位。旧草稿未填写距离时继承模板值。新增道具在客户端与服务端基线均包含且一致后才能继续编辑；升级后重启编辑器并刷新页面。

浏览道具时，在预览下方查看“掉落怪物”。同一怪物的重复物品槽合并为一行；列表来自当前 NPC 模板物品配置，不代表已覆盖全部脚本奖励或完成实际击杀掉落验收。新增草稿按新 ID 查询，不继承模板道具的掉落关系。数据读取失败可重试，道具编辑仍可使用；升级后需重启编辑器服务并刷新页面。

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests
npm --prefix editor test
```

多数集成测试依赖本地游戏资源及取证快照，纯源码检出不能直接复现完整测试结果。requirements-dev.txt 中的可选依赖用于复现静态分析。

## 目录

- editor：浏览器界面与 Three.js 预览。
- tools/xyj_content：文件解析、资源关联、草稿、快照与配置管理。
- tools/editor_server.py：仅监听本机回环地址的编辑器服务。
- tools/bootstrap.py：Windows 启动与专用环境准备。
- tests：解析、接口、状态隔离与安全边界测试。
- examples：道具修改示例。

部分工具用于历史本地取证或指定目标的部署验证，包含环境校验限制，不是通用部署入口。历史部署脚本要求通过 --share 显式指定 UNC 共享根目录，目标必须匹配本地静态快照证据及文件基线；不内置服务器地址。图形编辑器的自动覆盖仅使用已保存的目标设置，请求本身不能指定临时写入路径。共享路径使用运行编辑器的 Windows 账号权限，需要事先登录共享并具备读取、创建暂存文件及替换目标文件的权限。

## 当前限制

0.10.1 修正身体装备的自动匹配：使用装备实际种族／性别条件选择人物，按 ACT 的贴图编号和帧应用身体材质，校验实际图片资源；贴图目录中的“人共用”“人男”“天女”等名称不作为硬性适配限制。限制未知时自动模式仍明确拒绝，可手动选择人物作外观查看；身体装备的已知限制仍会约束手动选择。

模型以静态首帧预览为主，动画、染色、动态特效及部分装扮尚未完整还原。实例存档携带不等于运行中库存，模板生成判定不等于最终击杀掉率。完整游戏内验收仍需使用实际游戏环境进行。

脚本索引只沿已核验的指令边界、分支和入口建立可能生成关系，当前识别随机生成及指定坐标生成。遇到尚未解析的变长指令、对象／地图上下文切换会停止该路径，保留未覆盖统计；条件分支表示可能生成，不代表实时数量或刷新频率。脚本与游戏程序均只作静态读取，不会执行。
