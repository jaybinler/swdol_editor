# 轩辕剑网络版 · 道具工坊

Windows 本地内容编辑与查看工具，当前版本 **0.14.0**。

## 功能

- 按名称、编号和分类查看道具，展示原游戏图标及已确认属性。
- 支持 27 项数值属性编辑，包含武器伤害力／延迟／距离、六项抗性及体力／灵力回复；属性概览与当前表单同步，保留零值和负值。
- 回避率直接展示。原始御劲非零时保留原值；原始御劲为零且原始回避率非零时，御劲按用户确认规则跟随当前回避率显示，并标记“随回避率”。联动不修改御劲原始字段。
- 预览原始三维资源与部分人物穿戴效果，支持旋转、缩放和线框。
- 人物穿戴的“自动匹配”根据道具要求的种族和性别选择基础人物，按 ACT 应用经过校验的身体贴图；也可手动指定基础人物。
- 明确区分查看、编辑与新增道具。编辑时固定原 ID；新增时可按名称、编号、分类选择模板，复用原图标和模型。
- 新增自动建议双端及草稿均未占用的 ID；支持同一模板多次新增，草稿可重新打开、恢复表单和移除。
- 获取途径可同时添加怪物掉落、商店购买、任务奖励。每件道具最多新增一种怪物来源，成功掉落固定 1 件，展示实际可表达的掉率；地图用于筛选和核对怪物分布。
- 商店通过已有商品配置节点追加，保留原商品及原生定价；任务通过已有物品奖励节点追加，保留原任务条件。仅开放可完整解析的函数，未知指令不会强行写入。
- 获取配置随道具草稿保存，相关服务端编号脚本随补丁配套备份、覆盖与失败恢复。原生任务发奖按顺序执行，并非事务；背包不足、部分奖励成功后的重试行为需游戏验收。
- 保存本地草稿，点击后自动备份并覆盖已配置的双端文件；备份仅保留最近一次，支持失败回滚及中断恢复。切换前保护未暂存输入，旧版草稿保持兼容。
- 按出现地图查看 NPC 与怪物，统一预览模板基础外观。
- 新增或编辑怪物名称、说明、性别、等级、八项基础属性、掉落与已有技能；独立怪物草稿支持重开、恢复与编号冲突检查。
- 配置地图、坐标、朝向和数量，支持新增、移动、移除直接存档点；沿用原生随机刷新并显示实际等待范围。不同地图的独立间隔使用可见的不同 ID 变体。
- 复用旧怪物外观，或生成独立三轴缩放 ACT 资源；保留原动作数据。点击怪物导出后自动配套发布文件与地图点位，完成备份、回读核验、快照更新和草稿清理。
- 在工坊内编辑怪物动作网格的顶点、边、面、UV、骨骼与权重。支持按材质调色、替换 PNG、预览原生动作，以及发布独立模型和贴图。
- 搜索与地图切换立即清除旧详情和旧编号；精确编号被地图筛选隐藏时，提示已记录地图并提供跨地图定位，避免将筛选空结果误解为地图缺失。
- 每件道具提供“掉落怪物”列表，显示怪物名称、编号和地图；点击名称可直接进入 NPC 页签并精准选中，返回时保留道具未暂存内容。
- 地图索引合并存档关系与已解析的脚本生成关系；枯石等无直接存档的怪物也可按地图查找。关系保存在 v3 快照，离线查看无需原始脚本。
- v3 快照核验版本后，地图索引同时展开五槽刷新候选，保留来源路径、循环去重及跨地图复活保护；20088／20089 器奴可在通天柱找到。NPC 详情可展开候选并按编号跳转，变体不会被伪造为直接存档。
- v3 快照核验版本后，NPC 技能的同图召唤关系也纳入统一地图索引；20355 魔礼海元神通过 20086 魔礼海的“元神出窍”归入通天柱，详情标注召唤者与技能，召唤物不计为直接存档。
- 每种 NPC／怪物展示一份模板配置的物品清单，页面只显示“道具、掉率”，掉率为已计算的生成百分比。
- 集中配置游戏文件、NPC 快照与只读数据库连接，真实校验通过后才能保存；可用 Windows DPAPI 保护保存的数据库密码。

## 从源码运行

需要 Windows、Python 3.11 或更新版本，以及 Node.js／npm。

```powershell
git clone https://github.com/jaybinler/swdol_editor.git
cd swdol_editor/editor
npm ci
cd ..
.\启动道具编辑器.cmd
```

启动器会准备项目专用 Python 环境。打开本地页面右上角“设置”，选择匹配的客户端根目录、服务端 Object 文件及 NPC 数据来源，通过校验后保存。

本仓库只提供工具源码、测试和示例，不包含游戏客户端／服务端资源、数据库原始文件、NPC 快照、本机设置、密码、草稿、迁移包或内部研究记录。运行时需要自行准备游戏资源。

NPC 离线模式需要与服务端 Object 基线匹配的最小快照；数据库模式需要可读取 npcpool 与 npcpool_add_on 的连接、兼容 MySQL 客户端和区域目录。区域目录应包含地图配置、NewLocalServer.exe 与 ASM/TALK 编号脚本；只读校验后将解析关系写入快照。切换机器后重新定位路径、输入凭据并校验。数据源校验只读两张 NPC 表，页面使用本地快照；怪物自动发布仅执行已经核验的点位计划。旧 v1／v2 快照仍可查看，怪物编辑导出需要原生版本核验通过的 v3 快照。

## 新增与编辑怪物

升级后重启编辑器并刷新页面，进入“NPC与怪物”，选择模板后点击“编辑怪物”或“新增地图变体”。编辑保持原 ID；新增使用独立 ID，默认刷新候选均为自身。跨地图不同间隔需分别新增可见变体。

1. 修改模板信息。配置地图、XYZ、朝向、数量后，点击“加入点位修改”，再“暂存怪物”。未加入的输入会明确提示并阻止暂存，也可单独放弃本次点位输入。
2. 在设置中校验并保存双端目标。含地图点位变更时，须使用数据库模式，并保护保存有效密码。纯模板修改不要求写数据库。
3. 停止相关游戏服务和客户端，点击“导出并覆盖双端”，在同一次操作中勾选停服确认。程序自动发布三份双端表及配套 ACT、IDX、PLY、TEX 和点位数据库操作，完成回读并刷新基线／NPC 快照，移除已应用草稿，再定位当前怪物。
4. 写入独立 ACT 后，工坊改为读取客户端根目录中的新 Act。新增点仍继承明确来源的存档与原脚本，页面显示脚本编号；坐标仅做数值校验，未验证地形可通行。

道具和怪物共用最近一次自动备份 output/editor/backups/latest，以及最近一次正式补丁 output/editor/patches/latest。成功后清理两类旧正式补丁与旧备份；失败／中断保留恢复所需临时资料，恢复成功后再整理。设置、有效草稿、必要基线／快照与测试证据不在清理范围。最近一次备份自包含恢复资料，不依赖旧补丁包；原设置引用旧包中的输入会先复制并核验到独立基线目录，供恢复使用。

普通错误会恢复文件和数据库并保留草稿。涉及数据库的中断恢复不会在启动时默默执行：程序显示“恢复上次发布”，停服确认后恢复。若目标被第三方修改，程序保留资料并提示，避免覆盖新状态。MyISAM 和跨文件替换没有整体事务性。

成功但响应丢失时，页面查询持久回执，不重复写入；已提交的原补丁也禁止重复执行。独立命令行仍可仅校验补丁，或者在停服后发布／恢复：

```powershell
python tools/apply_creature_patch.py --patch "补丁目录"
python tools/apply_creature_patch.py --patch "补丁目录" --apply --server-stopped
python tools/apply_creature_patch.py --recover "output/editor/backups/latest" --server-stopped
```

**当前只保留最近一次恢复点，下一轮成功后不能回退到更早版本。** 320“始源女”的出现、可击杀和技能释放已由用户确认。其掉落、死亡刷新、重登和缩放资源的全动作效果待游戏内验收。外部模型转换、技能施放概率及冷却编辑待另行验证。

## 修改怪物模型与贴图

从“NPC与怪物 → 编辑怪物或新增地图变体 → 外观 → 修改模型与贴图”打开编辑器。选择动作模型后可编辑网格、材质与骨骼，并在原生姿态中预览。怪物使用多个动作模型时，可逐个切换编辑，其他模型继续复用原资源。保存模型草稿后返回暂存怪物，再按上述流程导出。发布后可重新打开同一个模型项目，继续编辑骨骼和权重。

每个顶点最多绑定四个骨骼。发布时将变形烘焙到原生动作姿态，保留原生分组用于挂点。贴图使用 RGB555 色彩和二值透明，导入尺寸上限为 2048 × 2048。新模型的实际游戏加载、动作与碰撞效果待验收。

## 新增与编辑道具

1. 编辑现有道具：选中道具，点击“编辑道具”，修改名称、说明和已开放的基础属性，再点击“暂存修改”。原 ID 固定。
2. 新增道具：点击道具库的“新增道具”，搜索并选择模板；也可在详情点击“以此为模板新增”。确认新 ID、名称与属性后点击“暂存新增”。
3. 新增继承原始基线模板，独立于该模板的修改草稿；同一模板可新增多件。编号建议不预留 ID，暂存时仍会核验占用。
4. 从“补丁草稿”重新打开可继续修改；“恢复表单”返回进入表单时或最近暂存的内容。“移除”只移除所选草稿。
5. 在设置中填写“服务端 Object.dbf 覆盖目标”，校验后保存。此项与“服务端 Object.dbf（读取基线）”独立，可以填写本机文件或已登录的 Windows 共享完整文件路径，例如 `\\服务器\共享名\qingfeng\Object.dbf`。
6. 核对草稿差异，再点击“导出并覆盖双端文件”。目标为配置中的服务端文件、客户端根目录下的 `Main/Object.dbf` 和 `Main/Language.DBF`。目标文件必须与编辑基线一致；高级客户端路径须与这两个 Main 文件一致。
7. 覆盖前备份到 `output/editor/backups/latest/`，包含本次原文件及必要的状态、路径和哈希清单。道具与怪物全程序共用一套最新备份和一个最新补丁，成功后清理旧正式资料。
8. 覆盖成功后自动载入新基线，清空本轮已应用草稿，保留旧工作区草稿，并在保持数据来源模式的同时更新 NPC 快照绑定；无需每次重新连接数据库。

升级到 0.10.0 后需重启编辑器服务并刷新页面，旧服务不会启用新的覆盖按钮。覆盖前应退出游戏并停止占用这些文件的服务，避免其他程序同时改写。文件覆盖完成不代表运行中的游戏已重新读取数据；加载后的实际效果仍需游戏内验收。

程序会先完整生成并校验补丁、完成本地备份并暂存所有替换文件，然后逐个替换、读回核验。覆盖中失败时回滚并保留草稿；若外部修改、共享断线或权限问题使回滚不能完成，将列出未恢复文件并保留备份。纯文件中断沿用启动恢复；涉及怪物数据库的未完成发布须停服确认后恢复。跨目录文件和数据库不具备整体原子性。

0.7.0 编辑范围新增抗火、抗水、抗风、抗雷、抗光、抗暗（整数 -128 至 127）及体力回复、灵力回复（整数 -32768 至 32767）。旧草稿缺少这些字段时从对应模板补齐。御劲显示联动由原始模板决定：若原始回避率与御劲均为零，之后只修改回避率不会启用联动；原始御劲非零时始终优先显示原始御劲。升级后同样需要重启编辑器并刷新页面。

## 开发与测试

0.9.0 将伤害力、延迟和距离集中到“武器属性”，可在概览查看并在编辑表单修改。0.9.1 起仅“武器/副手”分类显示这三项，其他类型的概览和表单均隐藏整个武器属性区域，原有数值及草稿保留。距离为有符号 16 位整数，伤害力同样为 16 位，延迟为 32 位；均沿用客户端原始显示值，不换算单位。旧草稿未填写距离时继承模板值。新增道具在客户端与服务端基线均包含且一致后才能继续编辑；升级后重启编辑器并刷新页面。

浏览道具时，在预览下方查看“掉落怪物”。同一怪物的重复物品槽合并为一行；列表来自当前 NPC 模板物品配置，不代表已覆盖全部脚本奖励或完成实际击杀掉落验收。新增草稿按新 ID 查询，不继承模板道具的掉落关系。数据读取失败可重试，道具编辑仍可使用；升级后需重启编辑器服务并刷新页面。

```powershell
python -m pip install -r requirements.txt
python tools/run_editor_tests.py
npm --prefix editor test
```

多数集成测试依赖本地游戏资源及取证快照，纯源码检出不能直接复现完整测试结果。requirements-dev.txt 中的可选依赖用于复现静态分析。

## 目录

- editor：浏览器界面与 Three.js 预览。
- tools/xyj_content：文件解析、资源关联、草稿、快照与配置管理。
- tools/editor_server.py：仅监听本机回环地址的编辑器服务。
- tools/bootstrap.py：Windows 启动与专用环境准备。
- tests：解析、接口、状态隔离与安全边界测试。
- examples：道具修改示例。

部分工具用于历史本地取证或指定目标的部署验证，包含环境校验限制，不是通用部署入口。历史部署脚本要求通过 --share 显式指定 UNC 共享根目录，目标必须匹配本地静态快照证据及文件基线；不内置服务器地址。图形编辑器的自动覆盖仅使用已保存的目标设置，请求本身不能指定临时写入路径。共享路径使用运行编辑器的 Windows 账号权限，需要事先登录共享并具备读取、创建暂存文件及替换目标文件的权限。

## 当前限制

0.10.1 修正身体装备的自动匹配：使用装备实际种族／性别条件选择人物，按 ACT 的贴图编号和帧应用身体材质，校验实际图片资源；贴图目录中的“人共用”“人男”“天女”等名称不作为硬性适配限制。限制未知时自动模式仍明确拒绝，可手动选择人物作外观查看；身体装备的已知限制仍会约束手动选择。

模型以静态首帧预览为主，动画、染色、动态特效及部分装扮尚未完整还原。实例存档携带不等于运行中库存；模板掉率采用用户已确认的原生语义，新增怪物的实际掉落仍需分别实测。完整游戏内验收仍需使用实际游戏环境进行。

脚本索引只沿已核验的指令边界、分支和入口建立可能生成关系，当前识别随机生成及指定坐标生成。遇到尚未解析的变长指令、对象／地图上下文切换会停止该路径，保留未覆盖统计；条件分支表示可能生成，不代表实时数量或刷新频率。脚本与游戏程序均只作静态读取，不会执行。
